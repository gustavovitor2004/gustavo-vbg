# Internationalisation (i18n)

## Overview

The site supports three languages:

| Code | Language | Default |
|------|----------|---------|
| `en` | English | Yes |
| `pt` | Portuguese | No |
| `es` | Spanish | No |

English is the default because it maximises SEO reach and international discoverability. Portuguese is included because Gustavo's primary client base is in Brazil. Spanish is included for broader Latin American reach.

---

## Architecture

The i18n system is custom — no library (next-intl, react-i18next, etc.) is used. It is a deliberately lightweight system for a portfolio site where translation volume is small.

### Key files

| File | Role |
|------|------|
| `src/i18n/translations.ts` | All translation strings keyed by dot-notation path |
| `src/context/AppContext.tsx` | Stores `lang` state, provides `setLang` and `t()` function |
| `src/components/Navbar.tsx` | Language selector UI |

### `t()` function

The `t()` function resolves a dot-notation key to the translation string in the current language.

```ts
// Usage in a component
const { t } = useApp();
const label = t("hero.available"); // "Available for work" / "Disponível para trabalho" / "Disponible para trabajo"
```

If a key is missing in the current language, the function falls back to the English string. If it is also missing in English, it returns the key itself as a string (fail-visible).

---

## Language Persistence

The selected language is stored in `localStorage` under the key `lang`. On page load, `AppContext` reads this value and initializes the language state. This means the language persists across sessions.

If `localStorage` is unavailable (SSR or private browsing without storage), the default language (`en`) is used.

```ts
// AppContext initialization
const stored = typeof window !== "undefined" ? localStorage.getItem("lang") : null;
const initial = (stored === "en" || stored === "pt" || stored === "es") ? stored : "en";
```

## Translation Key Conventions

### Naming

Keys use dot-notation with no more than three levels:

```
{section}.{element}
{section}.{element}.{variant}
```

**Good:**
```
hero.available
nav.work
sites.category.restaurant
servers.members
footer.year
```

**Bad:**
```
page.hero.top.right.availability.badge.text  // too deep
hAvlblBdge                                   // not readable
```

### Values

Translation values are plain strings. No HTML, no JSX, no markdown. If formatting is needed, split it into multiple keys.

**Good:**
```ts
"hero.tagline": "Building digital products that matter."
"hero.taglineSecondary": "From architecture to deployment, independently."
```

**Bad:**
```ts
"hero.tagline": "Building <strong>digital products</strong> that matter."
```

### Placeholders

Use `{placeholder}` syntax for dynamic values:

```ts
"footer.copyright": "© {year} Gustavo Gomes"
```

Replace in component:
```tsx
t("footer.copyright").replace("{year}", String(new Date().getFullYear()))
```

## Language Selector

### UI

The language selector in the Navbar shows the current language code in uppercase mono text: `EN`, `PT`, `ES`.

Clicking it opens a dropdown listing all three options. The active language is shown in `--accent` color.

### Mobile

On mobile, the language selector is inside the fullscreen overlay. Three buttons side-by-side: `EN · PT · ES`.

---

## Translation Coverage Requirements

Every user-facing string that:
- appears in the Navbar
- appears in the Footer
- is a section label or heading
- is a CTA button label

...must have translations in all three languages.

Strings that are not translated:
- Project titles (proper nouns)
- Tech stack names (TypeScript, Next.js, etc.)
- Social media handles (@gustavo_vbg)
- Phone numbers (+55 75 9985-96215)
- Server names (Trophi)

---

## Adding a New Translation

1. Add the key to `translations.ts` in all three languages simultaneously. Never add a key to one language without adding it to the others.

2. For any language you are not confident in, add a note comment:

```ts
// pt: needs review by native speaker
"section.newKey": {
  en: "New feature is live",
  pt: "Novo recurso disponível",  // needs review
  es: "Nueva función disponible",  // needs review
}
```

3. Update `20-I18N.md` (this file) if you are adding a new section or convention.

## Fallback Behavior

If a translation key is accessed but only exists in English (e.g., when adding a new key before all translations are complete):

1. The `t()` function returns the English value.
2. No error is thrown.
3. No visual difference — the English string is rendered.

This is intentional. A partially-translated site is better than a site that crashes or shows raw keys. However, treat missing translations as a bug to fix before next deploy.

---

## SEO and Language

The site currently does not use sub-paths (`/en`, `/pt`, `/es`) or `lang` attributes per page beyond the root `<html lang="en">`. This is a known limitation.

Future improvement: Set `<html lang={lang}>` dynamically and add `<link rel="alternate" hreflang="pt" href="...">` tags for each language variant.
